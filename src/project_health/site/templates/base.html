{# "Expand chart" dialog (issue #156): one native , shared by every chart on the page -- `static/chart_expand.js` fills it from whichever chart's Expand button was clicked, using that chart's own declared `data-chart-meta`. A native traps focus and closes on Esc on its own; no JS fallback for a browser old enough to lack it, same "progressive, not polyfilled" stance `
`/`` already takes for the collapsible sections above. The Expand button itself is JS-only (opening it does nothing without `chart_expand.js`), so it's hidden with JavaScript disabled rather than sitting there inert. #}

{# Main chart + its overview/brush strip sit directly under each other with no gap (orchestrator review of PR #157) -- grouped in their own flex container rather than relying on the dialog's own `gap`, which applies uniformly between every direct child. `chart_expand.js` hides the overview strip entirely (rather than leaving an empty gap) for a chart whose spec can't support a sensible single-panel overview (small multiples). #}
